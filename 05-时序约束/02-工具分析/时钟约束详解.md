## 1. 主时钟（Primary Clocks）

### 1.1 定义

主时钟是 FPGA 设计中**最基础、最根本的时钟信号**，通常由外部晶振、PLL 输出或专用时钟引脚输入，是其他时钟（如生成时钟、虚拟时钟）的时序参考基准。

### 1.2 核心属性

| 属性                        | 说明                          | 示例                          |
| ------------------------- | --------------------------- | --------------------------- |
| 时钟频率 / 周期                 | 时钟信号的振荡频率或周期，决定电路的最大工作速率    | 100MHz 时钟对应周期 10ns          |
| 占空比                       | 时钟高电平时间占一个周期的比例             | 50% 占空比（高电平 5ns，低电平 5ns）    |
| 时钟偏移（Clock Skew）          | 同一时钟信号到达不同寄存器时钟端的时间差        | 因布线长度差异导致的 0.2ns 偏移         |
| 时钟不确定性（Clock Uncertainty） | 时钟信号的固有抖动（Jitter）和工具预留的时序余量 | 0.3ns（包含抖动 0.1ns 和余量 0.2ns） |
| 时钟端口 / 网络                 | 时钟信号的输入端口或内部时钟网络            | 外部晶振输入端口 `clk_100mhz_in`    |

### 1.3 应用场景

所有同步电路的基础时序定义，例如：

- **CPU 核心时钟**：处理器内核的主工作时钟，如 ARM Cortex-M 系列的系统时钟
- **DDR 控制器时钟**：内存控制器的参考时钟，如 DDR3-1600 的 800MHz 时钟
- **通信接口时钟**：UART、SPI、I2C 等串行接口的波特率时钟
- **视频处理时钟**：图像传感器、显示控制器的像素时钟
- **高速串行接口**：PCIe、SATA、USB 等高速接口的参考时钟

### 1.4 约束示例（Xilinx Vivado Tcl）

```tcl
# 基础主时钟约束
create_clock -name clk_100mhz -period 10 [get_ports clk_in] -duty_cycle 50

# 设置时钟不确定性（包含抖动和余量）
set_clock_uncertainty -setup 0.3 [get_clocks clk_100mhz]
set_clock_uncertainty -hold 0.1 [get_clocks clk_100mhz]

# 设置时钟偏移（指定最大允许偏移）
set_clock_skew -max 0.2 [get_clocks clk_100mhz]

# 复杂示例：多个主时钟
create_clock -name clk_sys -period 10.0 [get_ports sys_clk]     # 100MHz 系统时钟
create_clock -name clk_ddr -period 2.5 [get_ports ddr_clk]     # 400MHz DDR时钟
create_clock -name clk_eth -period 8.0 [get_ports eth_clk]     # 125MHz 以太网时钟

# 为不同时钟设置不同的不确定性
set_clock_uncertainty -setup 0.2 [get_clocks clk_sys]
set_clock_uncertainty -setup 0.1 [get_clocks clk_ddr]
set_clock_uncertainty -setup 0.3 [get_clocks clk_eth]
```

### 1.5 最佳实践

#### 1.5.1 时钟引脚选择
- ==**优先使用专用时钟引脚**：如 FPGA 的 Global Clock Inputs (GCLK)，获得最优时钟分布==
- **避免使用普通 I/O 引脚**：普通引脚作为时钟输入会增加抖动和偏移
- **考虑差分时钟**：高频时钟（>200MHz）建议使用差分时钟输入

#### 1.5.2 时钟质量优化
- **使用 PLL 净化时钟**：通过 PLL 降低输入时钟的抖动
- **合理设置时钟不确定性**：根据实际测量或器件手册设置，避免过于保守
- **时钟树优化**：使用专用时钟缓冲器和时钟树结构

#### 1.5.3 约束编写规范
```tcl
# 推荐的约束模板
create_clock -name [时钟名称] \
             -period [周期值] \
             [get_ports [端口名称]] \
             -duty_cycle [占空比]

# 添加时钟属性
set_clock_uncertainty -setup [建立时间不确定性] [get_clocks [时钟名称]]
set_clock_uncertainty -hold [保持时间不确定性] [get_clocks [时钟名称]]
```

## 2. 虚拟时钟（Virtual Clocks）

### 2.1 核心概念

虚拟时钟是**不对应任何物理时钟信号**的逻辑时钟，主要用于约束 FPGA 与外部设备之间的接口时序，当外部设备的时钟未接入 FPGA 时，通过虚拟时钟模拟该外部时钟作为时序分析的参考基准。

### 2.2 应用场景详解

#### 2.2.1 约束外部输入信号（FPGA 接收外部数据）

当外部设备向 FPGA 发送数据时，若该外部设备的驱动时钟**未接入 FPGA**，需用虚拟时钟模拟外部设备的时钟。

**典型场景**：
- 外部 ADC 以 200MHz 时钟输出数据，但时钟不接入 FPGA
- 摄像头传感器输出图像数据，像素时钟不连接到 FPGA
- CPU 向 FPGA 发送并行数据，CPU 时钟不接入 FPGA

**约束示例**：
```tcl
# 创建虚拟时钟模拟外部ADC的200MHz时钟
create_clock -name VIRT_ADC_CLK -period 5.0

# 约束ADC数据输入相对于虚拟时钟的延迟
set_input_delay -clock VIRT_ADC_CLK -max 3.0 [get_ports ADC_DATA[*]]
set_input_delay -clock VIRT_ADC_CLK -min 1.0 [get_ports ADC_DATA[*]]

# 摄像头数据约束示例
create_clock -name VIRT_CAM_CLK -period 15.38  # 65MHz像素时钟
set_input_delay -clock VIRT_CAM_CLK -max 2.5 [get_ports {CAM_DATA[*] CAM_HSYNC CAM_VSYNC}]
set_input_delay -clock VIRT_CAM_CLK -min 0.5 [get_ports {CAM_DATA[*] CAM_HSYNC CAM_VSYNC}]
```

#### 2.2.2 约束外部输出信号（FPGA 向外部发数据）

当 FPGA 向外部设备输出数据时，若外部设备的接收时钟**未接入 FPGA**，需用虚拟时钟模拟外部设备的接收时钟。

**典型场景**：
- FPGA 向 LCD 输出显示数据，LCD 接收时钟不连接到 FPGA
- FPGA 向 DAC 输出数据，DAC 采样时钟不接入 FPGA
- FPGA 向外部存储器输出数据，存储器时钟独立

**约束示例**：
```tcl
# LCD显示接口约束
create_clock -name VIRT_LCD_CLK -period 15.38  # 65MHz显示时钟
set_output_delay -clock VIRT_LCD_CLK -max 2.5 [get_ports {LCD_RGB[*] LCD_HSYNC LCD_VSYNC LCD_DE}]
set_output_delay -clock VIRT_LCD_CLK -min -0.5 [get_ports {LCD_RGB[*] LCD_HSYNC LCD_VSYNC LCD_DE}]

# DAC输出约束
create_clock -name VIRT_DAC_CLK -period 10.0   # 100MHz DAC时钟
set_output_delay -clock VIRT_DAC_CLK -max 1.5 [get_ports DAC_DATA[*]]
set_output_delay -clock VIRT_DAC_CLK -min 0.2 [get_ports DAC_DATA[*]]
```

#### 2.2.3 约束跨时钟域路径

当 FPGA 内部逻辑与外部设备存在数据交互，且两者的时钟无直接物理关联时，虚拟时钟作为"桥梁"定义时序关系。

**约束示例**：
```tcl
# FPGA内部100MHz时钟
create_clock -name CLK_FPGA -period 10.0 [get_ports clk_fpga]

# 外部设备150MHz虚拟时钟
create_clock -name VIRT_EXT_CLK -period 6.667

# 定义两个时钟域的关系（如果有固定相位关系）
set_clock_groups -asynchronous -group [get_clocks CLK_FPGA] -group [get_clocks VIRT_EXT_CLK]

# 或者设置跨域路径的最大延迟
set_max_delay -from [get_clocks CLK_FPGA] -to [get_clocks VIRT_EXT_CLK] 5.0
```

### 2.3 虚拟时钟创建语法

```tcl
# 基本语法
create_clock -name [虚拟时钟名称] -period [周期] -waveform {[上升沿] [下降沿]}

# 示例
create_clock -name VIRT_CLK_100M -period 10.0                    # 100MHz，50%占空比
create_clock -name VIRT_CLK_200M -period 5.0 -waveform {0 2.5}   # 200MHz，50%占空比
create_clock -name VIRT_CLK_ASYNC -period 8.33 -waveform {0 4.165} # 120MHz，50%占空比
```

### 2.4 与物理时钟的区别

| 对比维度 | 虚拟时钟 | 物理时钟 |
|---------|---------|---------|
| 硬件信号 | 无实际硬件信号 | 有实际时钟信号 |
| 驱动对象 | 不驱动任何逻辑 | 驱动时序逻辑（寄存器等） |
| 主要用途 | I/O接口时序约束 | 内部逻辑时序约束 |
| 创建方式 | `create_clock -name` | `create_clock [get_ports]` |
| 时序分析 | 仅用于I/O路径分析 | 用于所有相关路径分析 |

### 2.5 最佳实践

#### 2.5.1 虚拟时钟命名规范
```tcl
# 推荐命名方式
create_clock -name VIRT_[设备名]_[频率]_CLK -period [周期]

# 示例
create_clock -name VIRT_ADC_200M_CLK -period 5.0
create_clock -name VIRT_LCD_65M_CLK -period 15.38
create_clock -name VIRT_UART_16M_CLK -period 62.5
```

#### 2.5.2 延迟值确定方法
```tcl
# 输入延迟计算：Tco_max/min + PCB_trace_delay + Package_delay
set_input_delay -clock VIRT_CLK -max [Tco_max + trace_max + pkg_max] [get_ports input_signals]
set_input_delay -clock VIRT_CLK -min [Tco_min + trace_min + pkg_min] [get_ports input_signals]

# 输出延迟计算：Tsu/Th + PCB_trace_delay + Package_delay  
set_output_delay -clock VIRT_CLK -max [Tsu + trace_max + pkg_max] [get_ports output_signals]
set_output_delay -clock VIRT_CLK -min [-Th + trace_min + pkg_min] [get_ports output_signals]
```

## 3. 衍生时钟（Generated Clocks）

### 3.1 定义与特点

**衍生时钟（Generated Clocks）** 是由 FPGA 内部已有的时钟（通常是物理时钟或其他衍生时钟）通过逻辑单元生成的时钟信号，具有以下特点：

- **依赖源时钟**：必须基于一个已存在的"源时钟"生成
- **驱动内部逻辑**：用于驱动 FPGA 内部时序逻辑
- **保持时序关联**：与源时钟保持明确的频率/相位关系

### 3.2 常见生成方式

#### 3.2.1 PLL/MMCM 输出时钟
```tcl
# 源时钟定义
create_clock -name CLK_IN -period 10 [get_ports CLK_IN]  # 100MHz输入

# PLL输出的衍生时钟（通常工具自动创建，也可手动约束）
create_generated_clock -name PLL_CLK_200M \
                       -source [get_ports CLK_IN] \
                       -multiply_by 2 \
                       [get_pins PLL_INST/CLKOUT0]

create_generated_clock -name PLL_CLK_50M \
                       -source [get_ports CLK_IN] \
                       -divide_by 2 \
                       [get_pins PLL_INST/CLKOUT1]
```

#### 3.2.2 自定义分频器
```tcl
# 2分频器衍生时钟
create_generated_clock -name DIV2_CLK \
                       -source [get_clocks CLK_IN] \
                       -divide_by 2 \
                       [get_registers DIV2_REG/Q]

# 4分频器衍生时钟
create_generated_clock -name DIV4_CLK \
                       -source [get_clocks CLK_IN] \
                       -divide_by 4 \
                       [get_registers DIV4_COUNTER/Q[1]]
```

#### 3.2.3 时钟多路选择器
```tcl
# 时钟MUX输出的衍生时钟
create_generated_clock -name MUX_CLK_100M \
                       -source [get_clocks CLK_100M] \
                       [get_pins CLK_MUX/Y]

create_generated_clock -name MUX_CLK_150M \
                       -source [get_clocks CLK_150M] \
                       [get_pins CLK_MUX/Y] \
                       -add
```

#### 3.2.4 时钟门控和反相
```tcl
# 时钟门控
create_generated_clock -name GATED_CLK \
                       -source [get_clocks CLK_IN] \
                       [get_pins GATE_INST/Y]

# 时钟反相
create_generated_clock -name INV_CLK \
                       -source [get_clocks CLK_IN] \
                       -invert \
                       [get_pins INV_INST/Y]
```

### 3.3 必须手动约束的场景

#### 3.3.1 自定义分频器
```verilog
// RTL代码示例：2分频器
always @(posedge clk_in or negedge rst_n) begin
    if (!rst_n)
        div2_clk <= 1'b0;
    else
        div2_clk <= ~div2_clk;
end

// 对应的约束
create_generated_clock -name DIV2_CLK \
                       -source [get_clocks CLK_IN] \
                       -divide_by 2 \
                       [get_registers div2_clk_reg/Q]
```

#### 3.3.2 时钟选择器
```verilog
// RTL代码示例：时钟MUX
assign mux_clk = sel ? clk_a : clk_b;

// 对应的约束（需要为每个可能的源时钟创建衍生时钟）
create_generated_clock -name MUX_CLK_A \
                       -source [get_clocks CLK_A] \
                       [get_nets mux_clk]

create_generated_clock -name MUX_CLK_B \
                       -source [get_clocks CLK_B] \
                       [get_nets mux_clk] \
                       -add
```

#### 3.3.3 复杂分频逻辑
```verilog
// RTL代码示例：3分频器
reg [1:0] div3_counter;
reg div3_clk;

always @(posedge clk_in or negedge rst_n) begin
    if (!rst_n) begin
        div3_counter <= 2'b00;
        div3_clk <= 1'b0;
    end else begin
        if (div3_counter == 2'b10) begin
            div3_counter <= 2'b00;
            div3_clk <= ~div3_clk;
        end else begin
            div3_counter <= div3_counter + 1;
        end
    end
end

// 对应的约束
create_generated_clock -name DIV3_CLK \
                       -source [get_clocks CLK_IN] \
                       -divide_by 3 \
                       [get_registers div3_clk_reg/Q]
```

### 3.4 衍生时钟约束语法详解

```tcl
create_generated_clock -name [衍生时钟名称] \
                       -source [源时钟对象] \
                       [-multiply_by 倍频系数] \
                       [-divide_by 分频系数] \
                       [-duty_cycle 占空比] \
                       [-phase 相位偏移] \
                       [-invert] \
                       [-add] \
                       [目标对象]
```

**参数说明**：
- `-source`：指定源时钟，可以是端口、引脚或已定义的时钟
- `-multiply_by`：倍频系数（与-divide_by互斥）
- `-divide_by`：分频系数
- `-duty_cycle`：占空比（0-100）
- `-phase`：相位偏移（度）
- `-invert`：时钟反相（相位偏移180度）
- `-add`：添加模式，用于同一节点的多个时钟定义

### 3.5 与虚拟时钟的区别

| 对比维度 | 衍生时钟 | 虚拟时钟 |
|---------|---------|---------|
| 存在形式 | 有实际硬件信号 | 无实际硬件信号 |
| 依赖关系 | 必须关联源时钟 | 独立定义 |
| 用途 | 驱动内部逻辑 | I/O接口约束 |
| 创建方式 | `create_generated_clock` | `create_clock` |
| 时序关系 | 与源时钟有确定关系 | 与其他时钟可能异步 |

### 3.6 最佳实践

#### 3.6.1 避免过度约束
```tcl
# 对于IP核生成的时钟，检查是否已自动创建
report_clocks -generated

# 如果已自动创建，无需手动约束
# 如果未自动创建，再手动添加约束
```

#### 3.6.2 正确指定源时钟路径
```tcl
# 推荐：使用具体的物理节点
create_generated_clock -name DIV_CLK \
                       -source [get_pins PLL_INST/CLKOUT0] \
                       -divide_by 2 \
                       [get_registers DIV_REG/Q]

# 避免：使用模糊的时钟名称
# create_generated_clock -source [get_clocks *] ...
```

#### 3.6.3 处理多源时钟
```tcl
# 对于时钟MUX，为每个可能的源创建衍生时钟
create_generated_clock -name MUX_CLK_SRC1 \
                       -source [get_clocks SRC1] \
                       [get_pins MUX/Y]

create_generated_clock -name MUX_CLK_SRC2 \
                       -source [get_clocks SRC2] \
                       [get_pins MUX/Y] \
                       -add

# 使用case analysis指定当前激活的时钟
set_case_analysis 0 [get_ports mux_sel]  # 选择SRC1
# 或
set_case_analysis 1 [get_ports mux_sel]  # 选择SRC2
```

## 4. 时钟组（Clock Groups）

### 4.1 核心概念

**时钟组（Clock Groups）** 用于将设计中的多个时钟划分为不同"组别"，明确告知时序分析工具不同组别的时钟之间不存在时序关联，从而：

- 避免分析无意义的跨时钟域路径
- 提高时序分析效率
- 减少虚假的时序违规报告

### 4.2 时钟组类型

#### 4.2.1 异步时钟组（Asynchronous）
用于完全独立、无固定相位关系的时钟。

```tcl
# 异步时钟组示例
create_clock -name CLK_A -period 10 [get_ports CLK_A]    # 100MHz
create_clock -name CLK_B -period 8 [get_ports CLK_B]     # 125MHz

set_clock_groups -name ASYNC_GROUPS \
                 -asynchronous \
                 [get_clocks CLK_A] \
                 [get_clocks CLK_B]
```

#### 4.2.2 互斥时钟组（Exclusive）
用于同一时刻只有一个时钟有效的场景。

```tcl
# 互斥时钟组示例（时钟MUX）
create_clock -name CLK_MODE1 -period 5 [get_ports CLK_IN] 
create_clock -name CLK_MODE2 -period 10 [get_ports CLK_IN] -add

set_clock_groups -name EXCLUSIVE_GROUPS \
                 -exclusive \
                 [get_clocks CLK_MODE1] \
                 [get_clocks CLK_MODE2]
```

#### 4.2.3 逻辑互斥时钟组（Logically Exclusive）
用于逻辑上互斥但可能同时存在的时钟。

```tcl
set_clock_groups -name LOGICAL_EXCLUSIVE_GROUPS \
                 -logically_exclusive \
                 [get_clocks CLK_TEST] \
                 [get_clocks CLK_NORMAL]
```

### 4.3 常见应用场景

#### 4.3.1 ==多时钟域系统（跨时钟域）==
```tcl
# 视频处理系统示例
create_clock -name CLK_VIDEO -period 15.38 [get_ports video_clk]    # 65MHz
create_clock -name CLK_AUDIO -period 81.38 [get_ports audio_clk]    # 12.288MHz  
create_clock -name CLK_CPU -period 10.0 [get_ports cpu_clk]         # 100MHz
create_clock -name CLK_DDR -period 2.5 [get_ports ddr_clk]          # 400MHz

# 将不相关的时钟域分组
set_clock_groups -name MEDIA_CLOCKS \
                 -asynchronous \
                 [get_clocks {CLK_VIDEO}] \
                 [get_clocks {CLK_AUDIO}] \
                 [get_clocks {CLK_CPU}] \
                 [get_clocks {CLK_DDR}]
```

#### 4.3.2 测试模式时钟
```tcl
# 正常模式和测试模式时钟
create_clock -name CLK_NORMAL -period 10 [get_ports sys_clk]
create_clock -name CLK_TEST -period 100 [get_ports test_clk]

set_clock_groups -name TEST_MODE_GROUPS \
```

### 4.6 最佳实践

#### 4.6.1 时钟组设计原则
1. **同源时钟同组**：衍生时钟与其源时钟应在同一组
2. **异步时钟分组**：无固定相位关系的时钟必须分组
3. **功能相关性**：按功能模块划分时钟组
4. **避免过度分组**：不要将有时序关系的时钟分到不同组

#### 4.6.2 约束编写模板

```tcl
                 -[asynchronous|exclusive|logically_exclusive] \
                 [get_clocks {时钟组1}] \
                 [get_clocks {时钟组2}] \
                 [get_clocks {时钟组3}]

# 示例

                 -asynchronous \
                 [get_clocks {clk_cpu clk_cpu_div2}] \
                 [get_clocks {clk_ddr clk_ddr_div4}] \
                 [get_clocks {clk_video}] \
                 [get_clocks {clk_audio}]
```

## 5. 总线偏移约束（Bus Skew）

### 5.1 核心概念

**总线偏移约束（Bus Skew Constraint）** 用于控制同一总线中多个信号之间的时序偏移，确保总线内所有信号在采样时刻的延迟差异处于可接受范围。

### 5.2 总线偏移的来源

#### 5.2.1 物理因素
- **布线长度差异**：总线信号在FPGA内部布线路径不同
- **负载差异**：部分信号连接更多的逻辑单元
- **驱动强度差异**：不同信号的驱动能力不同

#### 5.2.2 时序因素
- **时钟偏移**：时钟到达不同寄存器的时间差
- **逻辑延迟差异**：信号经过的组合逻辑延迟不同
- **工艺偏差**：制造工艺导致的器件参数差异

### 5.3 应用场景

#### 5.3.1 并行数据总线
```tcl
# 8位并行数据总线偏移约束
set_max_skew -to [get_ports DATA_BUS[*]] 0.5

# 16位地址总线偏移约束  
set_max_skew -to [get_ports ADDR_BUS[*]] 0.3

# 32位AXI数据总线
set_max_skew -to [get_ports {AXI_WDATA[*] AXI_WSTRB[*]}] 0.2
```

#### 5.3.2 控制信号组
```tcl
# DDR控制信号组
set_max_skew -to [get_ports {DDR_RAS DDR_CAS DDR_WE DDR_CS}] 0.1

# LCD控制信号组
set_max_skew -to [get_ports {LCD_HSYNC LCD_VSYNC LCD_DE LCD_CLK}] 0.3
```

#### 5.3.3 高速接口总线
```tcl
# LVDS数据总线
set_max_skew -to [get_ports LVDS_DATA[*]] 0.05

# 高速ADC接口
set_max_skew -from [get_ports ADC_DATA[*]] 0.1
```

### 5.4 约束语法详解

#### 5.4.1 基于时钟的偏移约束
```tcl
# 语法
set_max_skew -from [源对象] -to [目标对象] [偏移值]

# 示例：输出总线偏移
set_max_skew -to [get_ports OUTPUT_BUS[*]] 0.5

# 示例：输入总线偏移
set_max_skew -from [get_ports INPUT_BUS[*]] 0.3

# 示例：内部信号偏移
set_max_skew -from [get_registers SRC_REG[*]/Q] \
             -to [get_registers DST_REG[*]/D] 0.2
```

#### 5.4.2 相对信号间偏移
```tcl
# 数据总线相对于时钟的偏移
set_max_skew -from [get_ports DATA[*]] \
             -to [get_ports CLK] 0.1

# 控制信号相对于数据的偏移
set_max_skew -from [get_ports CTRL_SIGNALS[*]] \
             -to [get_ports DATA_SIGNALS[*]] 0.2
```

### 5.5 偏移值确定方法

#### 5.5.1 基于时钟周期的计算
```tcl
# 一般经验值：偏移 < 时钟周期的10-20%
# 100MHz时钟（10ns周期）：偏移 < 1-2ns
set_max_skew -to [get_ports BUS_100M[*]] 1.0

# 200MHz时钟（5ns周期）：偏移 < 0.5-1ns  
set_max_skew -to [get_ports BUS_200M[*]] 0.5
```

#### 5.5.2 基于接收端要求
```tcl
# 根据外部器件的建立/保持时间要求
# 外部器件Tsu=2ns, Th=1ns，则偏移应 < min(Tsu,Th) = 1ns
set_max_skew -to [get_ports EXT_DEVICE_BUS[*]] 1.0
```

#### 5.5.3 基于信号完整性分析
```tcl
# 根据仿真或测量结果确定
# 如果仿真显示最大偏移为0.3ns，设置约束为0.2ns（留余量）
set_max_skew -to [get_ports MEASURED_BUS[*]] 0.2
```

### 5.6 复杂总线偏移约束

#### 5.6.1 分组约束
```tcl
# 将大总线分组约束
set_max_skew -to [get_ports DATA_BUS[7:0]] 0.3    # 低8位
set_max_skew -to [get_ports DATA_BUS[15:8]] 0.3   # 高8位
set_max_skew -to [get_ports DATA_BUS[*]] 0.5      # 整体约束
```

#### 5.6.2 条件约束
```tcl
# 基于工作模式的条件约束
set_case_analysis 1 [get_ports MODE_SEL]
set_max_skew -to [get_ports MODE1_BUS[*]] 0.2

set_case_analysis 0 [get_ports MODE_SEL]  
set_max_skew -to [get_ports MODE2_BUS[*]] 0.4
```

#### 5.6.3 多时钟域约束
```tcl
# 不同时钟域的总线分别约束
set_max_skew -from [get_clocks CLK_A] \
             -to [get_ports BUS_A[*]] 0.3

set_max_skew -from [get_clocks CLK_B] \
             -to [get_ports BUS_B[*]] 0.2
```

### 5.7 与其他约束的协调

#### 5.7.1 与输入/输出延迟约束的关系
```tcl
# 先设置I/O延迟约束
set_input_delay -clock CLK -max 2.0 [get_ports INPUT_BUS[*]]
set_input_delay -clock CLK -min 0.5 [get_ports INPUT_BUS[*]]

# 再设置总线偏移约束（偏移值应小于延迟窗口）
set_max_skew -from [get_ports INPUT_BUS[*]] 0.3
```

#### 5.7.2 与时钟偏移的区别
```tcl
# 时钟偏移：同一时钟到达不同寄存器的时间差
set_clock_skew -max 0.1 [get_clocks SYS_CLK]

# 总线偏移：同一总线内不同信号的延迟差
set_max_skew -to [get_ports DATA_BUS[*]] 0.2
```

### 5.8 验证与调试

#### 5.8.1 偏移报告
```tcl
# 检查总线偏移违规
report_timing -max_paths 100 -slack_lesser_than 0 -group skew

# 报告特定总线的偏移
report_skew -to [get_ports DATA_BUS[*]]
```

#### 5.8.2 布局布线优化
```tcl
# 设置总线信号的布线优先级
set_property HIGH_PRIORITY true [get_nets DATA_BUS[*]]

# 约束总线信号的布线区域
create_pblock BUS_REGION
add_cells_to_pblock BUS_REGION [get_cells BUS_LOGIC/*]
resize_pblock BUS_REGION -add {SLICE_X0Y0:SLICE_X10Y10}
```

### 5.9 最佳实践

#### 5.9.1 约束设置原则
1. **渐进式约束**：从宽松到严格逐步收紧约束
2. **分层约束**：大总线分组约束，避免过度约束
3. **留有余量**：约束值应比实际需求严格20-30%

#### 5.9.2 设计优化建议
```tcl
# 使用专用总线资源
set_property IOSTANDARD LVDS [get_ports HIGH_SPEED_BUS[*]]

# 平衡总线信号的驱动强度
set_property DRIVE 12 [get_ports OUTPUT_BUS[*]]

# 使用差分信号减少偏移
set_property DIFF_TERM TRUE [get_ports DIFF_BUS_P[*]]
```

### 6.2 常见问题与解决方案

#### 6.2.1 时钟定义问题
```tcl
# 问题：重复定义时钟
# 错误示例
create_clock -name CLK1 -period 10 [get_ports clk_in]
create_clock -name CLK2 -period 10 [get_ports clk_in]  # 错误！

# 正确做法：使用-add选项或不同名称
create_clock -name CLK_MODE1 -period 10 [get_ports clk_in]
create_clock -name CLK_MODE2 -period 5 [get_ports clk_in] -add
```

#### 6.2.2 衍生时钟问题
```tcl
# 问题：源时钟路径错误
# 错误示例
create_generated_clock -name DIV_CLK \
                       -source [get_clocks *] \  # 模糊匹配
                       -divide_by 2 \
                       [get_registers div_reg/Q]

# 正确做法：明确指定源时钟
create_generated_clock -name DIV_CLK \
                       -source [get_ports clk_in] \  # 明确路径
                       -divide_by 2 \
                       [get_registers div_reg/Q]
```

#### 6.2.3 时钟组问题
```tcl
# 问题：相关时钟被错误分组
# 错误示例：将衍生时钟与源时钟分到不同组
set_clock_groups -asynchronous \
                 [get_clocks CLK_MAIN] \
                 [get_clocks CLK_MAIN_DIV2]  # 错误！

# 正确做法：相关时钟在同一组
set_clock_groups -asynchronous \
                 [get_clocks {CLK_MAIN CLK_MAIN_DIV2}] \
                 [get_clocks CLK_OTHER]
```
