## 1️⃣ 模块的输入与输出（I/O Interface）

| 信号        | 方向  | 位宽       | 类型    | 说明                  |
| --------- | --- | -------- | ----- | ------------------- |
| `i_clk`   | 输入  | 1 bit    | 时钟    | 主时钟                 |
| `i_reset` | 输入  | 1 bit    | 复位    | 同步复位（高电平有效）         |
| `i_ce`    | 输入  | 1 bit    | 时钟使能  | 控制是否在该周期执行操作        |
| `i_xval`  | 输入  | `IW` bit | 有符号整数 | 输入 X 坐标（初始向量）       |
| `i_yval`  | 输入  | `IW` bit | 有符号整数 | 输入 Y 坐标（初始向量）       |
| `i_phase` | 输入  | `PW` bit | 无符号整数 | 输入目标旋转角度（归一化到 0~2π） |
| `o_xval`  | 输出  | `OW` bit | 有符号整数 | 输出 X 值（旋转后，≈ cos）   |
| `o_yval`  | 输出  | `OW` bit | 有符号整数 | 输出 Y 值（旋转后，≈ sin）   |
| `i_aux`   | 输入  | 1 bit    | 辅助信号  | 可用于标记数据有效、通道 ID 等   |
| `o_aux`   | 输出  | 1 bit    | 辅助信号  | 与输出结果对齐的辅助标志        |

> 🔍 **关键点**：
> - 使用 `i_ce` 而不是 `start/done`，说明这是**流水线式、连续处理**的设计。
> - `i_phase` 是 **归一化角度**：`2^32 / (2π)`，即 360° 对应 `2^32`，0° 和 360° 都是 0。
> - `i_aux` → `o_aux` 构成**数据通道同步机制**，确保控制信号与数据对齐。

## 2️⃣ 模块的原理（Working Principle）

### 📌 核心功能：
对输入向量 `(i_xval, i_yval)` 进行**左旋转（逆时针）**，旋转角度为 `i_phase`，输出旋转后的坐标 `(o_xval, o_yval)`。

### 📌 数学基础：
CORDIC 旋转模式（Rotation Mode）：
$$
\begin{cases}
x_{i+1} = x_i - d_i \cdot y_i \cdot 2^{-i} \\
y_{i+1} = y_i + d_i \cdot x_i \cdot 2^{-i} \\
z_{i+1} = z_i - d_i \cdot \arctan(2^{-i})
\end{cases}
\quad \text{其中 } d_i = \text{sign}(z_i)
$$

### 📌 特殊设计亮点：
| 技术点 | 说明 |
|--------|------|
| **前置旋转（Pre-rotation）** | 将输入角度先归一化到 ±45° 范围内，减少迭代次数，提高精度 |
| **流水线结构（Pipelined）** | 使用 `reg xv[0:NSTAGES]` 数组，每级寄存，支持高吞吐率 |
| **符号扩展与工作位宽（WW）** | 输入扩展到 `WW` 位，防止迭代中溢出，保留精度 |
| **向偶数舍入（Round to Even）** | 避免统计偏差，提高长期精度 |
| **增益补偿提示** | 注释中给出增益 `K=1.164435`，并提供补偿乘法常数 `32'hdbd95b16` |

## 3️⃣ 实现步骤（Implementation Steps）

| 步骤 | 内容 |
|------|------|
| ① | **参数化设计**：使用 `localparam` 定义位宽、级数等，支持复用 |
| ② | **符号扩展**：将 `IW` 位输入扩展到 `WW` 位（左侧符号扩展 + 右侧补 0） |
| ③ | **前置旋转（Pre-rotation）**：<br> - 根据 `i_phase[29:27]`（最高 3 位）判断象限<br> - 调整 `xv[0]`, `yv[0]`, `ph[0]`，使相位落入 ±45° |
| ④ | **CORDIC 迭代（流水线）**：<br> - 使用 `generate for` 生成 `NSTAGES` 级流水线<br> - 每级根据 `ph[i]` 符号决定旋转方向<br> - 使用 `>>>` 实现右移（`2^{-i}`） |
| ⑤ | **舍入处理**：<br> - 向偶数舍入（银行家舍入法）<br> - 保留高 `OW` 位作为输出 |
| ⑥ | **辅助信号同步**：<br> - `i_aux` 通过 `ax` 移位寄存器延迟 `NSTAGES` 拍，与输出对齐 |

## 4️⃣ 使用场景、优点与缺点

| 项目 | 内容 |
|------|------|
| ✅ **使用场景** | - 软件无线电（SDR）中的载波生成与解调<br>- 电机控制（FOC）中的坐标变换<br>- 雷达/通信中的相位调制<br>- 任意波形发生器 |
| ✅ **优点** | - **流水线设计**：高吞吐率，单周期出结果<br>- **参数化**：易于复用不同位宽<br>- **前置旋转**：提高精度与收敛速度<br>- **舍入优化**：减少量化误差<br>- **开源 + LGPL**：可商用 |
| ❌ **缺点** | - **资源占用较高**：`NSTAGES` 级寄存器数组，占用较多 FF<br>- **固定级数**：无法动态调整精度<br>- **无 `done` 信号**：不适合突发模式，更适合连续流处理<br>- **需外部补偿增益 `K`**：输出未自动补偿 |

## 5️⃣ 代码结构分析（关键片段解读）

### 📌 1. **前置旋转（Pre-rotation）**
```verilog
case(i_phase[(PW-1):(PW-3)])
    3'b000: {xv[0], yv[0], ph[0]} <= {e_xval, e_yval, i_phase};        // 0°~45°
    3'b001: {xv[0], yv[0], ph[0]} <= {-e_yval, e_xval, i_phase-20'h40000}; // 45°~90°
    ...
endcase
```
> ✅ 作用：将任意角度映射到 ±45° 范围，减少 CORDIC 迭代的累积误差。

### 📌 2. **流水线迭代（Generate + For）**
```verilog
generate for(i=0; i<NSTAGES; i=i+1) begin : CORDICops
    always @(posedge i_clk)
    if (i_reset) ...
    else if (i_ce)
        if (ph[i][(PW-1)]) // 负相位
            {xv[i+1], yv[i+1], ph[i+1]} <= {xv[i] + (yv[i]>>>(i+1)), ...};
        else
            {xv[i+1], yv[i+1], ph[i+1]} <= {xv[i] - (yv[i]>>>(i+1)), ...};
end endgenerate
```
> ✅ 优势：完全流水线，每拍可处理新数据，吞吐率 = 时钟频率。

### 📌 3. **向偶数舍入（Round to Even）**
```verilog
assign pre_xval = xv[NSTAGES] + $signed({ {(OW){1'b0}}, xv[NSTAGES][(WW-OW)], {(WW-OW-1){!xv[NSTAGES][WW-OW]}} });
```
> ✅ 原理：如果被舍去的最高位为 1，且其余位不全为 0，则加 1；若全为 0，则向“偶数”舍入（避免统计偏差）。

### 📌 4. **辅助信号同步**
```verilog
ax <= { ax[(NSTAGES-1):0], i_aux };  // 移位寄存器
o_aux <= ax[NSTAGES];                // 延迟 NSTAGES 拍后输出
```
> ✅ 用途：可用于标记“这一拍的数据是某个特定输入的结果”，在调试或通道管理中非常有用。

## ✅ 一、核心结论（先看结论）

| 对比项 | 普通 CORDIC | 本实现（带前置旋转） |
|--------|-------------|------------------|
| **收敛范围** | ±90° | **±360°**（全象限） |
| **精度** | 受限于小角度逼近 | **更高**（大角度由前置处理） |
| **迭代次数** | 多（需逼近大角度） | **少**（只处理小角度） |
| **硬件开销** | 较低 | **略高**（多一级前置逻辑） |
| **增益** | 固定（~1.646） | **更稳定**（减少大角度旋转） |
| **适用场景** | 简单应用 | **高性能、全象限旋转** |

> ✅ **一句话总结：**
> 这个 CORDIC 使用 **前置旋转 + CORDIC 主循环** 的**混合架构**，  
> 在**全象限、高精度、低迭代误差**方面显著优于普通 CORDIC。

---

## 🔍 二、普通 CORDIC 的局限性

### 1. 收敛范围有限
- 普通 CORDIC 的收敛范围是 **±90°**
- 原因：第一级旋转是 `arctan(1) = 45°`，后续角度递减，总和趋近于 `99.7°`，但**不能稳定覆盖全象限**
- 如果输入角度是 `120°`，普通 CORDIC 无法精确逼近

### 2. 大角度逼近误差大
- 要旋转 `120°`，必须用很多小角度累加
- 由于角度是 `arctan(2^{-i})` 的离散值，逼近存在**量化误差**
- 尤其在 `90°~180°` 区间误差显著

### 3. 增益不稳定
- CORDIC 有固定增益 `K ≈ 1.646`（16 级）
- 但在大角度旋转时，由于逼近不精确，实际增益会有波动

---

## 🚀 三、本实现的“前置旋转”机制详解

### 🔧 前置旋转的核心思想：

> **把大角度旋转“分解”为：**
> 1. **整数倍 90° 的符号调整**（零增益，无误差）
> 2. **剩余的小角度由 CORDIC 主循环处理**

---

### 📌 前置旋转逻辑（代码解析）

```verilog
case(i_phase[(PW-1):(PW-3)])  // 取相位最高3位（决定象限）
```

| 最高 3 位 | 角度范围 | 操作 | 说明 |
|--------|----------|------|------|
| `3'b000` | 0°~45° | 不变 | 直接进入 CORDIC |
| `3'b001` | 45°~90° | `x = -y; y = x` | 逆时针转 90° |
| `3'b010` | 90°~135° | 同上 | 逆时针转 90° |
| `3'b011` | 135°~180° | `x = -x; y = -y` | 旋转 180° |
| `3'b100` | 180°~225° | 同上 | 旋转 180° |
| `3'b101` | 225°~270° | `x = y; y = -x` | 顺时针转 90° |
| `3'b110` | 270°~315° | 同上 | 顺时针转 90° |
| `3'b111` | 315°~360° | 不变 | 直接进入 CORDIC |

> ✅ **结果：无论输入角度是多少，进入 CORDIC 主循环时，剩余角度都在 ±45° 范围内**

## 🔄 四、工作流程对比

### 普通 CORDIC：
```
输入 (x, y, θ)
     ↓
[CORDIC 主循环] ← 用 16 个小角度逼近 θ
     ↓
输出 (x', y')
```

### 本实现（带前置旋转）：
```
输入 (x, y, θ)
     ↓
[前置旋转] ← 用符号调整处理大角度（±90°, ±180°）
     ↓
(x₀, y₀, θ₀)  // θ₀ ∈ [-45°, 45°]
     ↓
[CORDIC 主循环] ← 只需逼近小角度
     ↓
输出 (x', y')
```

## 📊 五、优势分析

### 1. ✅ **全象限支持（±360°）**
- 前置旋转处理了所有象限的符号
- CORDIC 主循环只负责精细调整
- 实现了**真正的全象限旋转**

### 2. ✅ **更高精度**
- 大角度由**精确的符号翻转**实现（无误差）
- 小角度由 CORDIC 逼近，误差小
- 避免了“用小角度逼近大角度”带来的累积误差

### 3. ✅ **更少的有效迭代**
- 普通 CORDIC：16 级全用于逼近
- 本实现：前置旋转处理了“大步长”，CORDIC 只需处理“微调”
- 虽然还是 16 级，但**每级的贡献更有效**

### 4. ✅ **增益更稳定**
- CORDIC 增益 `K` 与迭代路径有关
- 由于前置旋转减少了大角度旋转的需求，**增益波动更小**

### 5. ✅ **资源利用更高效**
- 虽然多了一级逻辑，但：
  - 减少了对高精度 CORDIC 的依赖
  - 可以用更少的级数达到相同精度
  - 符号翻转是**零成本**（只需取反）

## ⚠️ 六、代价（Trade-off）

| 缺点 | 说明 |
|------|------|
| **额外逻辑** | 需要 `case` 语句和多路选择器 |
| **延迟增加** | 多一级流水线（但可接受） |
| **控制复杂** | 需要判断象限 |

> 但这些代价远小于带来的精度和范围提升。

---

## 📌 七、为什么用最高 3 位判断？

- `PW = 20`，`2^20` 表示 `360°`
- 最高 3 位可以表示 `8` 个区间，每个 `45°`
- 正好将 `360°` 分为 `8` 个 `45°` 区间
- 便于判断是否需要 `±90°` 或 `±180°` 旋转

> - 实现了**性能与资源的最优平衡**
