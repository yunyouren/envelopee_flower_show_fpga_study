## 一、理论基础：核心概念与数据表示

### 1.1 位宽（Bit Width）的本质
- 所有信号都有固定位宽，如 `reg [7:0] a` 表示 8 位无符号数。
- 位宽不匹配会导致：
  - 截断（Truncation） → 精度丢失
  - 符号误判 → 有符号数变为正数
  - 溢出（Overflow） → 计算错误

### 1.2 核心预处理操作

| 操作        | 目的                             | 适用场景                     |
|-------------|----------------------------------|------------------------------|
| **符号扩展**（Sign Extension） | 保持有符号数的符号和数值不变       | 负数扩展、CORDIC、滤波器       |
| **零扩展**（Zero Extension）   | 扩展无符号数，高位补零             | 地址、计数器、无符号乘法       |
| **截断**（Truncation）         | 降低位宽，可能丢失精度             | 输出量化、资源优化             |
| **饱和截断**（Saturation）     | 截断前判断是否溢出，防止数值跳变   | 音频、图像处理                 |
| **位对齐**（Alignment）        | 统一不同模块的数据位宽             | 流水线、跨模块接口              |

### 1.3 有符号 vs 无符号：关键区别

| 特性         | 有符号数 (`signed`)           | 无符号数 (`unsigned`)         |
|--------------|-------------------------------|-------------------------------|
| 最高位       | 符号位（1 = 负，0 = 正）       | 普通数据位                     |
| 扩展方式     | 必须符号扩展                   | 可零扩展                       |
| 运算结果     | 自动按补码处理                 | 按模运算处理                   |
| Verilog 声明 | `reg signed [7:0] a`           | `reg [7:0] a`（默认无符号）    |

> [!TIP]  
> 在 Verilog 中，**只有显式声明 `signed` 的信号才会被当作有符号数处理**。否则即使数值为负，也会被当作正数解释。

## 二、语法结构与常用模板

### 2.1 符号扩展（Sign Extension）

```verilog
// 模板：将 IW 位有符号数扩展为 WW 位（WW > IW）
assign extended = { {(WW - IW){signal[IW-1]}}, signal };
```

- `signal[IW-1]`：提取符号位
- `{(WW - IW){...}}`：重复符号位 `(WW - IW)` 次
- 示例：8 位 → 16 位
  ```verilog
  assign out = { {8{in[7]}}, in };  // 8 位符号扩展为 16 位
  ```

### 2.2 零扩展（Zero Extension）

```verilog
// 模板：将 IW 位无符号数扩展为 WW 位
assign extended = { {(WW - IW){1'b0}}, signal };
```

- 示例：8 位地址 → 32 位总线
  ```verilog
  assign addr_32 = { 24'b0, addr_8 };
  ```

### 2.3 截断（Truncation）

```verilog
// 直接截断高位
assign truncated = wide_signal[LW-1:0];  // 从宽信号取低 LW 位
```

> [!WARNING]  
> 截断有符号数时必须先判断是否溢出，否则可能产生严重错误。

### 2.4 饱和截断（Saturation）

```verilog
// 示例：16 位有符号数截断为 8 位，带饱和
always @(*) begin
    if (wide > 127)
        narrow = 8'd127;
    else if (wide < -128)
        narrow = 8'd128;  // 即 -128
    else
        narrow = wide[7:0];
end
```

## 三、实践案例：CORDIC 中的位宽预处理

以 `cordic_a.v` 第 83–84 行为例：

```verilog
assign e_xval = { {i_xval[(IW-1)]}, i_xval, {(WW-IW-1){1'b0}} };
assign e_yval = { {i_yval[(IW-1)]}, i_yval, {(WW-IW-1){1'b0}} };
```

### 笔记分析要点

| 部分 | 含义 | 作用 |
|------|------|------|
| `{i_xval[(IW-1)]}` | 提取符号位 | 实现符号扩展（1 位） |
| `i_xval` | 原始数据 | 保留原始位 |
| `{(WW-IW-1){1'b0}}` | 补零 | 在**低位**补零，提升精度（非扩展动态范围） |

> [!EXAMPLE] 为什么低位补零？
> - 这不是传统“高位扩展”，而是**定点小数精度扩展**
> - 假设 `i_xval` 是 Q 7.8 格式（8 位整数 + 8 位小数），扩展后变为 Q 15.16，**提升小数精度**
> - 低位补零 = 增加小数位 = 提高 CORDIC 迭代精度

### 总位宽计算
$$
\text{总位宽} = 1\text{（符号扩展）} + IW + (WW - IW - 1) = WW
$$

✅ 完美匹配目标工作位宽 `WW`。

## 四、动手实验：测试模块设计

```verilog
module bit_extension_test;
    parameter IW = 8;   // 输入位宽
    parameter WW = 16;  // 工作位宽

    reg signed [IW-1:0] test_input;
    wire signed [WW-1:0] extended_output;

    // 符号扩展 + 低位补零（提升精度）
    assign extended_output = { {test_input[IW-1]}, test_input, {(WW-IW-1){1'b0}} };

    initial begin
        $monitor("Input: %d (%b), Output: %d (%b)", 
                 test_input, test_input, extended_output, extended_output);

        test_input = 8'b10000001; // -127
        #10;
        test_input = 8'b01111111; // +127
        #10;
        $finish;
    end
endmodule
```

> [!SUCCESS] 预期输出：
> ```
> Input: -127 (10000001), Output: -32512 (111111111000000100000000)
> Input: 127 (01111111), Output: 32512 (000000000111111100000000)
> ```
> 注意：输出数值变化，但**比例关系保持不变**，用于定点运算。

### 一、定点数 Q 格式基础回顾

定点数用 **Qm. N** 表示：
- **m**：整数部分位数（含符号位）
- **n**：小数部分位数
- 总位宽 = m + n
- 最小可表示单位（分辨率） = $2^{-n}$

例如：
- **Q 7.8**：7 位整数（含 1 位符号位），8 位小数，共 16 位
  - 分辨率 = $2^{-8} = 1/256 \approx 0.00390625$
- **Q 15.16**：15 位整数（含符号位），16 位小数，共 32 位
  - 分辨率 = $2^{-16} = 1/65536 \approx 0.000015258789$

> ✅ **位数越多，小数精度越高，量化误差越小。**

---

### 二、扩展操作的数学本质

原始代码：
```verilog
assign e_xval = { {i_xval[(IW-1)]}, i_xval, {(WW-IW-1){1'b0}} };
```

假设：
- `IW = 16`（输入是 16 位，如 Q 7.8）
- `WW = 32`（工作位宽为 32 位）
- 则扩展为：`{sign, i_xval, 15{1'b0}}`

我们来拆解这个操作：

| 部分 | 位数 | 含义 |
|------|------|------|
| `{i_xval[15]}` | 1 位 | 符号位（保持有符号性） |
| `i_xval` | 16 位 | 原始数据（Q 7.8） |
| `15'b0` | 15 位 | **在低位补零** |

#### 关键：**在低位补零 = 增加小数位**

- 原始 `i_xval` 是 **Q 7.8**：小数部分 8 位
- 扩展后总位宽 32 位，其中：
  - 整数部分：仍为 7 位（符号 + 6 位整数）
  - 小数部分：8 + 15 = **23 位**
- 所以新格式是：**Q 7.23**（不是 Q 15.16，但思路一致）

> 📌 注意：你提到的 Q 15.16 是另一种常见扩展方式（整数部分也扩展），但此处是 **小数精度扩展**，更适用于 CORDIC。

---

### 三、为什么“低位补零”能提升精度？

我们用一个具体数值演示：

假设 `i_xval = 16'b11111000_11000000`，表示 Q 7.8 格式的数：

- 二进制：`11111000.11000000`
- 整数部分：`11111000`（补码） = -8
- 小数部分：`.11000000` = $0.75$
- 实际值 ≈ **-8.75**

扩展后：
```verilog
e_xval = {1'b1, 16'b11111000_11000000, 15'b0}
       = 32'b1_11111000_11000000_000000000000000
```

- 新格式：**Q 7.23**
- 小数部分变为 23 位，分辨率 = $2^{-23} \approx 1.19 \times 10^{-7}$
- 数值仍为 ≈ **-8.75**，但表示更精确

> ✅ **数值未变，但表示精度大幅提升**，减少了后续计算中的**量化误差**。

---

### 四、在 CORDIC 等迭代算法中的意义

CORDIC 是一种**迭代逼近算法**，每一步都涉及角度累加和向量旋转，其精度直接受输入数据和中间计算的**小数位数**影响。

#### 问题：如果小数位太少？
- 每次旋转角度的表示不精确
- 累积误差大
- 最终结果偏差明显

#### 解决方案：提升工作位宽的小数精度
- 输入从 Q 7.8 → Q 7.23
- 中间计算使用高精度定点数
- 最终输出再根据需要量化回低精度

这就像：
> 用 **毫米刻度** 的尺子做中间计算，最后结果四舍五入到 **厘米**，比直接用厘米尺子更准确。

---

### 五、对比：高位扩展 vs 低位补零

| 扩展方式 | 操作 | 目的 | 适用场景 |
|---------|------|------|----------|
| **高位符号扩展** | `{ {N{sign}}, data }` | 扩大整数范围，防溢出 | 大数值运算、累加器 |
| **低位补零扩展** | `{ data, {N{1'b0}} }` | 提升小数精度，减小量化误差 | CORDIC、滤波器、高精度计算 |

> 🔍 在你的例子中，`{sign, i_xval, zeros}` 是 **两者结合**：
> - `sign`：确保有符号性
> - `i_xval`：保留原始值
> - `zeros`：增加小数位 → **精度提升**

---

### 六、总结：为什么说“提升小数精度”？

| 维度 | 说明 |
|------|------|
| **数学本质** | 低位补零 = 增加小数位数 = 分辨率提高 |
| **数值影响** | 原始值不变，但表示更精确 |
| **工程意义** | 减少 CORDIC 等算法的量化误差，提升最终精度 |
| **资源代价** | 使用更多位宽（如 32 位代替 16 位），但值得 |

✅ 所以，这种扩展不是为了表示更大的数，而是为了在**高精度计算中减少舍入误差**，是数字信号处理中的常见优化手段。

其他位宽相关内容：
**log₂(N)**通常出现在**数字信号处理（如滤波、累加运算）的位宽设计**中，核心是根据输入信号位宽和运算需求，推导输出端需要的位宽，以避免数据溢出或精度损失，简要解析如下： 1. **核心构成含义** - **log₂(N)**：对应“N次累加运算”带来的位宽扩展。比如对N个输入信号求和时，最大可能的和是“单个输入最大值×N”，而N的二进制表示需要log₂(N)位（向上取整，如N=8时log₂(8)=3，需3位扩展），这部分是为了容纳累加后的数值范围，防止溢出。 - **28**：通常是**输入信号本身的位宽**（或基础位宽），比如若原始输入是28位的数字信号（如ADC采样的28位数据、FPGA内部处理的28位并行信号），这部分位宽需保留以保证原始信号的精度，再叠加累加扩展的log₂(N)位，最终得到输出总位宽。 2. **典型应用场景** 最常见于你之前提到的**MA滤波器（或累加器）** ：比如对N个28位的输入信号求和，再乘以1/N。求和时最大数值需28 + log₂(N)位（28位基础位宽+累加扩展位），后续乘1/N（本质是右移操作，不增加位宽），因此输出端需预留(log₂(N)+28)位，确保运算过程中无溢出、精度不丢失。
