## 核心调试流程与方法论

我们摒弃了“手动点击”的原始方式，建立了一套自动化、可重复的专业流程。
总结：
1.灵活使用批处理
2.加载顶层 Testbench 模块进行仿真，并禁用优化， ==-novopt== 是解决信号被优化的关键
找不到图形，图形不显示都可以用==-novopt== 
3.仿真时间与死区之类的时间不匹配, 仿真时间过短, 死区未发挥作用;
4.Pll 的 rset 重置应该注意, 时钟要导出来看
5.信号被综合, 开始模拟时不要勾选综合
#    -novopt 是解决信号被优化的关键
### **1. `clean_and_run.bat`：永远从“干净的石板”开始**

这是我们整个流程的入口。通过一个简单的批处理脚本，我们实现了“一键式”的清理与执行。

```batch
@echo off
:: 1. 清理旧战场：删除上一次编译产生的work库、波形文件和日志
echo Cleaning previous simulation files...
if exist work rmdir /s /q work
if exist vsim.wlf del vsim.wlf
if exist transcript del transcript

:: 2. 启动ModelSim进入后台命令行模式，并执行do脚本
echo Starting ModelSim simulation...
vsim -c -do run_sim.do

echo Simulation finished.
pause
```

> **[💡] 方法论核心**: 每次仿真前都彻底删除旧的编译产物（尤其是 `work` 库），可以从根本上避免因文件残留、版本不一致等原因导致的“玄学”问题。**这是保证仿真结果确定性的黄金法则。**

### **2. `run_sim.do`：仿真的自动化“总导演”**

这个脚本是整个仿真的核心，它像一位导演，精确地指挥着 ModelSim 的每一步动作。

```tcl
# 1. 创建工作库 (如果不存在)
if {[file exist work]} {
    # work库已存在
} else {
    vlib work
}

# 2. 编译所有需要的Verilog源文件
vlog -work work -vopt +acc ./rtl/dds_main.v
vlog -work work -vopt +acc ./sim/tb_dds_main.v

# 3. 加载顶层Testbench模块进行仿真，并禁用优化
#    -novopt 是解决信号被优化的关键
vsim -novopt work.tb_dds_main

# 4. 添加所有需要观察的波形信号
#    注意区分顶层信号和uut内部信号的路径
add wave -radix hex /tb_dds_main/clk_in
add wave -radix hex /tb_dds_main/led
add wave -radix unsigned /tb_dds_main/dac_data
add wave -radix binary /tb_dds_main/pwm_out

# 添加内部信号以供调试
add wave -divider "Internal Signals"
add wave -radix hex /tb_dds_main/uut/cnt
add wave -radix hex /tb_dds_main/uut/PWM_in
add wave -radix hex /tb_dds_main/uut/PWM_DDS_accumulator

# 5. 运行仿真
run 50us

# 6. (可选) 退出仿真器
# quit -f
```

##  3.“聪明反被聪明误” - ModelSim 的自动优化**

- **Symptom (症状)**: 路径明明正确，但某些内部信号（如 `PWM_in`）依然添加失败。
- **Diagnosis (诊断)**: ModelSim 的默认优化 (`-vopt`) 机制非常“激进”。如果一个信号（特别是 `wire` 类型）没有直接或间接地影响到最终的输出端口，优化器会认为它是“冗余”的，并将其“优化掉”以提升仿真性能。
- **Prescription (处方)**:
    1.  **全局禁用优化 (The "Big Hammer" 🔨)**: ==在 `vsim` 命令后添加 `-novopt` 参数。这会告诉仿真器“保留所有信号，不要自作主张”。==
    2.  **代码层面防止优化 (The "Surgical Strike" 🔪)**: 对于某些顽固的 `wire` 型信号，即便加了 `-novopt` 也可能被移除。终极解决方案是：
        -   **将 `wire` 改为 `reg`**: `wire PWM_in;` -> `reg [23:0] PWM_in;`
        -   **为 `reg` 提供明确的驱动**: 使用一个组合逻辑 `always @(*)` 块来驱动它。
            ```verilog
            // 在 dds_main.v 中
            always @(*) begin
                PWM_in = PWM_DDS_accumulator;
            end
            ```
        这相当于告诉编译器：这个 `reg` 是一个有实际物理意义的锁存器，必须保留。
