# 信号被综合,无法添加
最重要的方法是保持信号的可见性，避免被综合优化。

若要抓取的信号被综合，可在信号定义后面添加/*synthesis keep*/注释，保持信号不被综合。


          
关于死区信号输入`DeadBandTime_Input[9:0]`只能添加`[8:1]`的问题，这通常与Signal Tap Logic Analyzer的信号选择限制有关：

## 可能的原因分析

### 1. Signal Tap的信号可见性限制

**层次结构问题**:
```
完整信号路径: DSP_PWM_autotest.DeadBandTime_Input[9:0]
Signal Tap可能只能看到: DeadBandTime_Input[8:1]
```

**可能原因**:
- `DeadBandTime_Input[0]` (最低位) 可能被优化掉
- `DeadBandTime_Input[9]` (最高位) 可能在当前设计中未使用

### 2. 编译优化导致的信号丢失

**位宽使用分析**:
从代码可以看到死区时间的实际使用范围：
```verilog
// 0.5μs死区: DeadBandTime_Input = 50  (6 bits足够)
// 2μs死区:   DeadBandTime_Input = 200 (8 bits足够) 
// 3μs死区:   DeadBandTime_Input = 300 (9 bits足够)
```

**最高位[9]可能未使用**:
- 最大值300 = 9'b100101100
- 实际只需要9位，第10位([9])可能被优化

**最低位[0]可能被优化**:
- 如果死区时间总是偶数，最低位可能被优化

### 3. 解决方案

**方案A: 添加可用的位**
```
推荐监控位: DeadBandTime_Input[8:1] (8 bits)
覆盖范围: 2-510 (足够覆盖测试范围)
优势: 能观察到所有有效的死区变化
```

**方案B: 强制保留所有位**
在代码中添加约束，防止优化：
```verilog
// 在DSP_PWM_autotest.v中添加
(* keep *) reg [9:0] DeadBandTime_Input;
```

**方案C: 分组监控**
```
高位组: DeadBandTime_Input[9:5] (5 bits)
低位组: DeadBandTime_Input[4:0] (5 bits)
```

### 4. 当前测试的实际需求

**测试值分析**:
```
0.5μs死区: 值=50  = 10'b0000110010
2μs死区:   值=200 = 10'b0011001000  
3μs死区:   值=300 = 10'b0100101100
```

**关键观察位**:
- `DeadBandTime_Input[8:1]` 完全覆盖了测试范围
- 位[0]对于这些测试值都是0，影响不大
- 位[9]只在值≥512时才有用，当前测试用不到

### 5. 推荐的Signal Tap配置

**最佳配置**:
```
监控信号: DeadBandTime_Input[8:1] (8 bits)
观察范围: 2-510 (步长为2)
实际测试值:
- 50  → 观察到: 8'b00011001 (25)
- 200 → 观察到: 8'b01100100 (100)  
- 300 → 观察到: 8'b10010110 (150)
```

**注意事项**:
- 显示的值是实际值除以2
- 仍然可以清楚区分三个死区设置
- 不影响死区功能的观察和验证

### 6. 验证方法

**确认信号可用性**:
1. 在Signal Tap中展开信号树
2. 查看`DSP_PWM_autotest`模块下的信号
3. 确认哪些位可以添加到监控列表

**替代观察方法**:
如果某些位不可用，可以观察：
```
- test_state[3:0]: 确认当前测试阶段
- 实际PWM输出的变化: 验证死区效果
- PosedgeDelay模块内的count信号: 直接观察计数过程
```

总结：`DeadBandTime_Input[8:1]`已经足够观察当前的死区测试，缺失的位[0]和[9]不会影响死区功能的验证。
